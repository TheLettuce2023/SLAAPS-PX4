# C1C-S2: actual Commander receipt capture, no admission

2026-09-20. Master design release: implement the bounded capture experiment
below under the user's existing C1 disarmed/output-disabled SITL approval.
Independent review, build audits and two fresh runs are required for acceptance.
This is not live diagnostic admission, mode/control integration or Phase 2 exit.

## Outcome and source scope

C1C-S1 structurally checks supplied receipts but cannot establish that real
Commander changes were captured. S2 instruments the actual source commits in
an isolated source view, captures queued evidence, and independently checks it
after normal shutdown. Ordinary checkout sources and C1A remain untouched.

Allowed new paths: Tools/research_sitl/px4_attachment/c1c_capture/** and this
design/verification documentation. Exact reviewed overlay changes ONLY copied
Commander.cpp, Commander.hpp and commander/CMakeLists.txt. Private real ancestor
directories must replace the existing source-view symlink ancestors before any
patching. Validate that every modified target is a regular file inside the
owned /var/tmp build area; never follow a checkout symlink for a write.
Record actual base bytes (including local changes), patch bytes, derived source
bytes, full input registry and executable. Drift or mismatched patch context
fails; do not force a patch. No permanent hook enters stock firmware here.

Pinned source hook sites are in C1C_STATE_RECEIPT_CONTRACT.md: initial state
after constructor arm/nav initialization, each arm/disarm assignment, each
active-nav assignment including the termination overwrite, and a periodic
Sample at the loop boundary before ordinary coalesced publication. The hook
observes the actual pair; it does not alter, reject, undo or suppress a state
change. No event is emitted for an assignment with an unchanged pair.
Samples detecting an unexplained state change permanently fail capture instead
of inventing a missing Transition. Every mutation seam must have a reviewed
exact patch context and synthetic helper coverage. A future upstream writer
added elsewhere requires renewed source review.

## Producer, bootstrap and delivery ownership

Commander owns one capture producer for its instance. The collector/CLI is not
an admission owner. Before Commander construction, a synchronous bootstrap
command opens and retains C orb_subscribe descriptors for the queued receipt
topic and separate producer-summary topic. Unlike a lazily attached C++
Subscription, this creates the unadvertised nodes before Initial is published.
It rejects an already-published stream or repeated bootstrap. No fabricated
Initial, shadow state, transport packet or mode flag is published.

Bootstrap receives explicit nonzero producer, observer and clock-lifetime IDs
generated by the owned runner for that fresh process. The producer claims its
reserved identity once; in-process restart/rebind is rejected. Initialization
must be synchronized before constructor access (release/acquire or a mutex),
not merely a non-atomic global flag. There is no external endpoint or signing
claim; this remains the cooperative trusted-local diagnostic environment.

Use external uORB message definitions, available only in the dedicated external
configuration. Receipts carry the S1 source fields with native hrt timestamp
and before/after raw arm/nav pair. The finite queue depth is explicit. Delivery
sequence increments for every Initial/Transition/Sample; transition epoch only
for a changed pair. Reserve/check counters before emission. Publication failure,
exhaustion, lost bootstrap/lifetime or a state contradiction permanently fails
the capture producer. Never publish an apparently healthy later state to hide it.

No callback into a checker, exporter or admission logic is registered inside the
publisher's uORB lock. The collector drains through copy/poll. Source code may
publish a diagnostic receipt only; there are no control/actuator publishers.
The eventual source-change-versus-admission race remains UNSOLVED because this
slice has no admission owner or decision path. Do not claim atomic live trust.

At Commander destruction/normal stop, publish a separate final producer summary
with lifetime, last emitted/attempted sequence, transition epoch, retained actual
state and sticky capture status. After Commander has stopped, the collector
drains all remaining receipts and reconciles this summary. Requiring summary
and exact final counters detects a missing tail even when no subsequent receipt
exposes a gap. Missing summary or incomplete shutdown is failure, never a pass.

## Build/runtime and evidence boundaries

Dedicated Linux POSIX SITL, native non-lockstep/non-proxy clocks. Reuse the
existing C1A minimal board selection and Commander parameter metadata, not its
startup order or probe. Allow only Commander, required diagnostic commands and
the new capture module; no MAVLink receiver, estimator, Gazebo bridge, flight
controllers, allocator, output driver, actuator test or research admission code.
Preserve strict builtins/module/driver and advertised-topic audits. Inspect the
generated compile commands to confirm the hook and producer source appear only
in the isolated configuration and that forbidden clocks/modules are absent.

Runner owns a fresh /var/tmp source/build/cache/runtime tree and PX4 instances;
builds are serial, with no mounts or reused simulator cache. No install/fetch,
arming, Offboard/vehicle-command injection, powered hardware or non-owned
process control is permitted. Keep COM_ARM_ON_BOOT=0 and COM_ARMABLE=0.
Startup sequence: bootstrap; Commander start; bounded capture window; Commander
stop; final drain/summary check; topic snapshot; completion marker; normal PX4
shutdown. Cleanup may stop only processes created by this runner.

Reviewed runtime-check refinement: the post-stop topic snapshot lists only
still-advertised nodes. Require queued receipt/summary topics; permit but do not
require Commander-owned single-slot state topics, which are unadvertised during
destruction. Keep the exact topic allowlist and queue/instance checks. This
snapshot is not an all-run publication inventory; source/build inspection and
complete receipt replay remain mandatory. Stage exact startup bytes under the
owned runtime and bind them by hash because the pinned PX4 shell launcher does
not quote its script path. Retained failures are in the verification document.

Producer and collector timestamps both call the same native PX4 hrt function;
record their exact source/build provenance and check nonzero ordered readings.
This does not qualify the cross-process guidance clock map. Capture timing
reports age and missing/stale evidence; no operational state freshness budget
is invented. S1 remains standalone host-only and must not be compiled into PX4
by spoofing its host marker. S2's independent evidence checker validates source
continuity and raw time ordering without claiming diagnostic readiness.

Full actual receipts, observer receipt times and final summary must be retained
without PX4_INFO line truncation. Use a dedicated owned evidence file or direct
full-length stdout records with checked write results. Do not let evidence I/O
run in the producer commit hook. Runtime errors, timeouts and partial files stay
retained as incomplete/failure. An evidence sink must not block Commander stop.

## Predeclared tests and acceptance

Host producer/helper tests: missing and repeated bootstrap/claim; valid Initial;
unchanged assignment; arm-to-disarm and double-nav transitions; Sample state
contradiction; timestamp regression; delivery/transition exhaustion; publish
failure and sticky failure; final-summary truth after failure. These state
changes are synthetic helper fixtures, never live arm/mode commands.

Independent evidence-checker negatives: missing/duplicate Initial or summary,
lost interior receipt, lost tail, duplicate/reordered/replayed receipt, changed
lifetime, wrong before-state/epoch, omitted transition, fabricated healthy
summary, nonfinite/wrong-type/truncated records, source/receive time regression,
Armed actual run evidence, unapproved module/topic, stale source/artifact hashes,
missing completion or forced process termination. Corruption tests must rehash
modified data so semantic detection is actually exercised.

Review overlay ownership and bootstrap-before-constructor order before building.
Run fresh strict host Debug/repeated Release/ASan+UBSan tests; inspect exact
isolated PX4 configuration before execution; run two fresh disarmed processes.
Accept only complete source-bound evidence with matching final summary and no
forbidden publisher/module. Actual captures may contain no transitions; do not
mislabel synthetic transition tests as observed live transitions.

Preserve all existing work and stock Gazebo/Cessna identity. On success the next
gate is trusted-input synchronization/estimator/clock/operator-loss and explicit
live diagnostic profile integration—not arming, control output or flight.
No additional human direction is required for this capture-only experiment.
